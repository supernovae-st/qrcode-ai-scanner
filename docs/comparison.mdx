## The three properties that matter

<CardGroup cols={3}>
  <Card title="100% local" icon="shield-check">
    The scan runs **in the user's browser** (wasm) or on **your server**
    (native) — the image never leaves the device. No third-party decode
    API, no upload, nothing to leak, GDPR-trivial.
  </Card>
  <Card title="Instant" icon="bolt">
    Clean codes decode in **3-10 ms**; production templates average
    **~45 ms**; the deep artistic ladder is budget-bounded (you choose the
    worst case). No network round-trip — the latency floor of any cloud
    decode API is already 10× our typical full scan.
  </Card>
  <Card title="Categorized" icon="tags">
    Every detection tells you WHAT it is — `symbology` (QR · EAN-13 ·
    Data Matrix · 19 kinds) and `payload.kind` (url · wifi · gs1 ·
    me_card · 13 kinds) — so UIs route instead of regex-guessing.
  </Card>
</CardGroup>

## Before → after on qrcode-ai.com

The landing's verify flow ran `qr-scanner-wechat@0.1.3` (a CNN-based
wasm decoder) inside a hand-tuned retry loop. Field by field:

| | Before (qr-scanner-wechat) | After (this scanner) |
|---|---|---|
| Verify calls per generation | up to **3** (HIGH/MEDIUM/LOW canvas filter loop) | **1** |
| Preprocessing | manual: per-type contrast/brightness/blur presets in app code | internal: a deterministic 5-stage ladder (binarization · channels · contrast boosts · morphological closes · erasure rescue) |
| "Quality" meaning | *which filter level happened to work* | a real **0-100 margin score**: 6 stress axes + structural checks + Reed-Solomon unused-error-correction |
| Output | `result.text` — one string | typed `ScanReport`: symbology, payload classification, geometry, score, ISO grade card, hints, trace |
| Blob/dot template styles (a generator OUTPUT class) | **0/3 filter levels decoded** | decoded (morphological close rungs — probe-calibrated on the template corpus) |
| Logo-occluded codes | fails past the RS error wall | erasure rescue decodes through **30% center occlusion** (vs 20%) |
| Wrong-decode protection | none — a miscorrection reads as success | UEC margin catches it (`low_correction_margin` distrust signal — proven on the public zxing corpus) |
| Barcodes / other symbologies | QR only | **19 symbologies**, labeled |
| Determinism | not guaranteed (CNN) | bit-for-bit reproducible (no RNG) |
| Feedback to the generator | none | machine-actionable hints (`fix_finder_pattern`, `raise_error_correction`, …) |
| Import an existing code | impossible | drop / browse / **paste** → decode locally → editor prefilled with the detected type |
| Verifiable claims | — | measured: zxing ground-truth **170/179** (beats the reference thresholds on all 6 suites) · production templates **15/15** |

Bundle honesty: ~797 KB gz all-symbologies (the incumbent was ~1 MB;
a QR-only build drops ~180 KB — documented escape hatch).

## Versus cloud decode APIs

| | Cloud decode API | This scanner |
|---|---|---|
| Privacy | image uploaded to a third party | never leaves the device |
| Latency | network RTT + queue (100-1000 ms) | 3-50 ms typical, budget-bounded worst case |
| Cost | per-call forever | zero marginal cost |
| Offline / flaky network | dead | works |
| Rate limits | yes | no |
| Sovereignty | vendor ToS can change | AGPL code you can read, pin and fork |

## What the categorization unlocks

```json
{ "symbology": "ean13",
  "payload": { "kind": "gs1", "gtin": "09506000134352", "conformant": true } }
```

One field tells the UI it's a retail barcode; the second hands it a
validated GTIN. The same shape routes wifi joins, vCards, GS1 Digital
Links (retail-ready badge), crypto URIs — without a single regex in app
code. The full taxonomy: [payloads](/api/report) ·
[symbologies](/api/report#detection).
