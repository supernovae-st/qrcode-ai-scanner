## API

```ts
import { scan, scanSync, version } from "@supernovae-st/qrcode-ai-scanner";
import type { ScanReport, ScanOptions } from "@supernovae-st/qrcode-ai-scanner";

// async on the libuv pool — NEVER blocks the event loop
const report: ScanReport = await scan(imageBuffer, {
  profile: "full",        // "full" | "fast" | "frame"   (default full)
  budgetMs: 1500,         // wall-clock bound; 0 = unbounded
  maxDimension: 4096,     // anti-DoS — LOWER THESE for untrusted uploads
  maxPixels: 16_000_000,
  alphaBackground: "auto", // background under transparent pixels:
                          // "auto" | "white" | "black" | "none" | "#rrggbb"
                          // (opaque inputs untouched; result in report.alpha)
  signal: controller.signal, // cancels QUEUED tasks (see note)
} satisfies ScanOptions);

const sync = scanSync(buffer, { profile: "fast" }); // scripts only
```

<Warning>
`signal` rejects tasks still QUEUED on the pool (and pre-aborted signals
reject immediately with `AbortError`). A RUNNING scan is not interrupted —
it completes within its `profile`/`budgetMs` bound. Budget is the real
latency control — and a report it cut says so: `trace.budget_exhausted`
is `true`, empty detections are then not final, and a `null` score beside
a detection means "not judged", never 0. `budgetMs: 0` is unbounded and
reproducible; unset keeps the profile default (full 4000 · fast 800 ·
frame 80 ms). The budget clock starts once the image is decoded and
normalized: `maxDimension` and `maxPixels`, not `budgetMs`, bound the
decode itself.
</Warning>

## Server recipe (Nitro/Express upload endpoint)

```ts
export default defineEventHandler(async (event) => {
  const body = await readRawBody(event, false);
  try {
    const report = await scan(body, {
      profile: "full", budgetMs: 2000,
      maxDimension: 4096, maxPixels: 16_000_000,
    });
    if (!report.detections.length) return { ok: false, reason: "no_qr" };
    const d = report.detections[0];
    const untrusted = report.hints.some(h => h.hint === "low_correction_margin");
    // null = not judged (a budget cut, or no score in this profile), never 0
    return { ok: true, text: d.content.text, kind: d.payload.kind,
             score: report.score?.value ?? null,
             final: report.trace.budget_exhausted === false, untrusted };
  } catch (e) {
    const code = (e as Error).message.match(/QRS-\d{3}/)?.[0];
    throw createError({ statusCode: code === "QRS-001" ? 422 : 413 });
  }
});
```

`d.content.text` is a complete reading of the payload's bytes
(`d.content.raw`, base64: the original bytes for the QR family, the
decoding engine's reading for other symbologies) unless
`d.content.charset === "unknown"` — the
only lossy value: then there is no verified reading, use `raw`. The
`Charset` type has six values (`utf8`, `shift_jis`, `latin1`, `gb18030`,
`eci`, `unknown`); give an exhaustive switch a default arm, since a later
release can add values (each a complete reading). Deduplicate on
`symbology`, `raw`, `fnc1` and `eci`, never on `text`.

Errors reject with `[QRS-xxx]`-tagged messages ([catalog](/api/errors)).
The report shape is the [one contract](/api/report).
