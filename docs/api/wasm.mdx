```bash
npm i @supernovae-st/qrcode-ai-scanner-wasm
```

`wasm-pack` web target: the `.wasm` resolves via `import.meta.url`.
Typed returns (`ScanReport`) ship in the package.

## Compatible initialization

```ts
import { loadScanner } from "@supernovae-st/qrcode-ai-scanner-wasm/auto";
const scanner = await loadScanner();
const report = scanner.scan_image(bytes, "full");
const loadedVariant = scanner.variant; // simd | compatible
```

Use this additive entry in both the module worker and any main-thread fallback.
It checks real WASM features in the calling realm before compiling the scanner,
then fetches only one binary. Imports are safe during SSR; initialization still
belongs to client/worker execution. Repeated and concurrent calls share one
promise, including an initialization failure. An explicit user retry can create
one fresh `createScannerLoader()`; there is no blind retry or automatic reload.

`ScannerInitError` preserves its native `cause`, stable `code`, selected
`variant` and optional HTTP `status`. Missing WASM, unsupported baseline features,
explicitly unavailable SIMD, loader imports, asset network/HTTP/read failures,
invalid headers, ambiguous WASM validation, compilation and instantiation have
separate codes. A validation failure in an unknown asset can reflect malformed
code or unexpected features. Inspect the actual asset and native cause instead
of attributing every error to SIMD, browser age or CPU. These JS-only diagnostics
do not change the Rust `QRS-xxx` catalog or any scan report fields.

The compatible module requires mutable globals, bulk memory, sign extension,
nontrapping conversions, multivalue and reference types. It removes the SIMD
requirement; it does not promise compatibility with every WASM-capable browser.
The package README documents the baseline probe, feature-limited build and
factory options. Physical devices, real Safari and historical browser floors
need their own acceptance evidence.

## Existing explicit SIMD API

```ts
import init, { scan_image, scan_frame, version }
  from "@supernovae-st/qrcode-ai-scanner-wasm";

await init(); // once — fetches + instantiates the .wasm

// encoded bytes (PNG/JPEG/WebP/GIF)
// args: bytes, profile?, max_dimension?, max_pixels?, budget_ms?,
//       score_skip_axes?, score_skip_checks?, alpha_background?
//       (alpha_background: "auto" | "white" | "black" | "none" | "#rrggbb"
//        — the background under transparent pixels; result in report.alpha)
const report = scan_image(bytes, "full", undefined, undefined, 1500);

// raw RGBA frames (live camera) — defaults to the `frame` profile
const ctx = canvas.getContext("2d")!;
const img = ctx.getImageData(0, 0, canvas.width, canvas.height);
const frame = scan_frame(new Uint8Array(img.data.buffer),
                         canvas.width, canvas.height);
```

<Warning>
The scan runs **synchronously on the calling thread**. In UI contexts
either pass `budget_ms` (the verify flow uses 1500 ms) or move the call
into a Web Worker. `budget_ms: 0` (or any value that is not above 0, NaN
included) means unbounded (reproducible); unset keeps the profile default.
A fractional budget is truncated to whole milliseconds, so a value strictly
between 0 and 1 cuts the scan before its first stage. The budget clock
starts once the image is decoded and normalized, so decoding a large image
is bounded by `max_dimension` and `max_pixels`, not by `budget_ms`; the
budget then stops planned work at attempt granularity, and the bounded
work `spec/02-profiles.md` § Budget semantics lists may finish past it. A
report the budget cut says so (`trace.budget_exhausted === true`): a
`null` score beside a detection then means "not judged" — never read it
as 0.
</Warning>

## Bundler notes

<AccordionGroup>
  <Accordion title="Vite / Nuxt">
    Exclude from dependency pre-bundling — esbuild breaks the
    `import.meta.url` wasm resolution:

    ```ts
    vite: { optimizeDeps: { exclude: ["@supernovae-st/qrcode-ai-scanner-wasm"] } }
    ```
  </Accordion>
  <Accordion title="Lazy loading">
    The release build reports the actual raw and gzip sizes; use the size
    of the version you install when setting a page-weight budget.
    Load it with the feature that needs it
    (dynamic `import()` in an async chunk) and memoize `init()` —
    **reset the memo if init rejects**, or one network error bricks the
    feature until reload:

    ```ts
    let ready: Promise<unknown> | null = null;
    ready ??= init().catch(err => { ready = null; throw err; });
    await ready;
    ```
  </Accordion>
  <Accordion title="Camera loop">
    Use `scan_frame` (no PNG roundtrip) at `frame` profile; throttle to
    ~5 fps — decoding every frame buys nothing.
  </Accordion>
</AccordionGroup>

Failures throw `JsError` with `[QRS-xxx]`-tagged messages
([catalog](/api/errors)).
